# Monebra Perfume — متجر إلكتروني

منصة تجارة إلكترونية كاملة لعلامة **Monebra Perfume**: متجر عام + لوحة تحكم
إدارية + إدارة مخزون وطلبات وتوصيل.

---

## التشغيل السريع

```bash
npm install
cp .env.example .env      # ثم عدّل القيم
npm run db:migrate        # إنشاء قاعدة البيانات
npm run db:seed           # بيانات أساسية + محتوى تجريبي
npm run seed:admin        # إنشاء حساب مدير (تفاعلي)
npm run dev
```

المتجر على <http://localhost:3000> ولوحة التحكم على `/admin`.

## قواعد لا تُخالَف

1. **الأسعار تُحسب على الخادم فقط.** السلة تحمل `variantId + quantity` لا غير.
   أي مبلغ قادم من المتصفح يُتجاهل.
2. **كل المبالغ أعداد صحيحة** بالوحدة الصغرى (`src/lib/money.ts`). لا تستخدم
   `float` لتمثيل مال.
3. **بيانات المتجر في قاعدة البيانات.** لا أسعار توصيل ولا أرقام هواتف ولا
   مدن ولا نصوص تسويقية داخل الكود — كلها من `settings` أو الجداول.
4. **المكوّنات لا تصل إلى Prisma.** كل قراءة أو كتابة تمر عبر `lib/services/`.
5. **الألوان من المتغيرات فقط** (`var(--surface-raised)` وأخواتها) حتى يعمل
   المكوّن في وضعَي المتجر الليلي والنهاري وفي لوحة التحكم الفاتحة بلا
   تعديل. لون صريح مثل `bg-ink-900` يعمل في وضع واحد وينكسر في الآخر.
6. **العطور «مستوحاة من».** يُمنع عرض أي منتج على أنه المنتج الأصلي، ويُمنع
   استخدام شعارات العلامات الأصلية.
7. **`notFound()` تُستدعى في `generateMetadata` أيضًا.** إن اكتفينا باستدعائها
   في مكوّن الصفحة، يُثبّت Next حالة 200 عند نجاح البيانات الوصفية فيستحيل
   إرجاع 404 حقيقية، وتُفهرس روابط منتجات غير موجودة.
8. **لا `loading.tsx` على مستوى مجموعة `(storefront)`.** وجوده ينشئ حدود
   Suspense حول كل صفحة فيبدأ البث بحالة 200 قبل تنفيذ `notFound()`.
9. **كل ما يمسّ الطلب أو المخزون داخل معاملة واحدة.** خصم المخزون يستخدم
   `updateMany` بشرط `stock >= quantity` ويتحقق من عدد الصفوف — هذا هو
   الحارس ضد البيع الزائد عند الطلبات المتزامنة.
10. **التتبّع يشترط رقم الطلب والهاتف معًا.** أرقام الطلبات متسلسلة، وبدون
    الهاتف يستطيع أي شخص قراءة عناوين العملاء.
11. **الصلاحية تُفحص على الخادم في كل صفحة وكل نقطة نهاية.** إخفاء الروابط
    في الشريط الجانبي تحسين للتجربة لا حماية — `requireAdmin` في نقاط
    النهاية و`requirePageAccess` في الصفحات هما الحماية الحقيقية.
12. **الجلسات معتمة لا JWT.** نخزّن تجزئة الرمز فقط، فتسجيل الخروج أو
    تعطيل الحساب يُبطلها فورًا. تغيير كلمة المرور يُنهي كل جلسات صاحبها.
13. **كل `params` في مسار ديناميكي يمرّ عبر `decodeSlug`.** الروابط العربية
    تصل من المتصفح مُرمَّزة بالنسبة المئوية (`%D8%A8...`)، والبحث بها في
    قاعدة البيانات لا يجد شيئًا فتُرجع 404 لمنتج موجود. اللاتينية لا تكشف
    الخطأ لأنها لا تُرمَّز أصلًا. افحصه يدويًا بفتح رابط منتج باسم عربي.
14. **`minPrice` عمود مخزَّن يجب تحديثه مع كل تغيير في الأحجام أو تفعيلها.**
    عليه يعتمد الترتيب بالسعر في SQL. أي مسار ينشئ أو يعدّل حجمًا خارج
    `createProduct`/`updateProduct` عليه استدعاء `refreshMinPrice`، وإلا ظهر
    المنتج بسعر صفر في الترتيب بينما يعرض سعره الحقيقي.
15. **كل تحويل إلى `/admin/login` بسبب جلسة غير صالحة يحمل `?expired=1`.**
    الوسيط يعمل على الحافة بلا قاعدة بيانات فلا يعرف إلا وجود الكوكي لا
    صلاحيته؛ بدون هذه العلامة تنشأ حلقة تحويل لا نهائية تمنع الدخول أصلًا.
16. **الباقة منتج بنوع `bundle` لا كيان منفصل**، فترث الصور والسيو والسلة
    والتقييمات. مخزونها مستقل عن مخزون أصنافها لأنها تُجهَّز مسبقًا كوحدة —
    ولذلك تنبّه اللوحة عند نفاد أحد أصنافها. ولا تُعشَّش باقة داخل باقة.
17. **وضع العرض يُكتب على `<html data-theme>` قبل أول رسم.** يفعل ذلك سكربت
    متزامن صغير في `<head>` مصدره `src/lib/theme.ts`. لا تنقل هذه الحالة إلى
    `useState`: الخادم لا يعرف ما في `localStorage`، فأي قراءة أثناء الرسم
    الأول تعطي عدم تطابق في الترطيب ووميضًا أبيض على كل تنقّل. `ThemeToggle`
    يقرأها بـ `useSyncExternalStore` من الـ DOM مباشرة.
18. **شعاران لا واحد.** `logoUrl` نسخة فاتحة للوضع الليلي و`logoUrlLight`
    نسخة داكنة للنهاري، وتخفي CSS إحداهما حسب `data-theme` — لا اختيار في
    جافاسكربت، وإلا ومض الشعار الخطأ لحظة الترطيب. شعار فاتح وحده على ورق
    عاجي يكاد يختفي. يُبنى الاثنان بـ `npm run brand`.
19. **محوّل قاعدة البيانات يُختار من `DATABASE_URL` لا من الكود**
    (`src/lib/db-adapter.ts`). كان كل ملف يستورد محوّل SQLite صراحةً، فالنشر
    على PostgreSQL يتطلّب تعديل أربعة ملفات على الخادم — وأخطرها
    `create-admin.ts`: لو بقي على SQLite لأنشأ حساب المدير في ملف محلي بلا
    رسالة خطأ، ثم يفشل الدخول بلا سبب ظاهر. `provider` في `schema.prisma`
    يبقى تعديلًا يدويًا واحدًا لأن Prisma يقرأه وقت البناء.

## تدفّق الطلب

```
السلة (localStorage: variantId + quantity فقط)
      ↓
/api/checkout/quote  →  إعادة تسعير من قاعدة البيانات + رسوم المدينة/المنطقة
      ↓                  (نفس دالة computeOrderTotals التي يستخدمها الحفظ)
POST /api/orders     →  تحديد معدّل + Zod + فخّ للآليّات
      ↓
┌── معاملة واحدة ────────────────────────────────────────┐
│ إنشاء/تحديث العميل                                      │
│ خصم المخزون بشرط stock >= qty  ← الحارس ضد البيع الزائد │
│ توليد رقم الطلب من عدّاد ذرّي   ← MON-10001              │
│ إنشاء الطلب + الأصناف بنسخة كاملة (snapshot)            │
│ تسجيل حركات المخزون + تحديث مبيعات المنتج               │
│ تسجيل استخدام الكوبون                                   │
│ إشعار المدير + تنبيه المخزون المنخفض + حدث تحليلي        │
└─────────────────────────────────────────────────────────┘
      ↓
/order/MON-10001  →  صفحة التأكيد (noindex)
/track            →  التتبّع برقم الطلب + الهاتف
```

### حالات الطلب

```
جديد → مؤكد → قيد التجهيز → خرج للتوصيل → تم التسليم
  ↓      ↓         ↓             ↓            ↓
  └──────┴─────────┴─────────────┴────────→ ملغي / مرتجع
                                            (يُعيد المخزون مرة واحدة)
```

الانتقالات المسموحة معرّفة في `ORDER_STATUS_TRANSITIONS` وتُفرض على الخادم.
علامتا `stockApplied` و`stockRestored` تمنعان الخصم أو الإرجاع المزدوج.

### الأدوار

| الدور | ما يستطيعه |
| --- | --- |
| **مدير عام** | كل شيء، بما فيه الإعدادات والمستخدمين والسجلات |
| **مدير** | المنتجات، الطلبات، المخزون، العملاء، المدن، الكوبونات، المحتوى |
| **مسؤول الطلبات** | الطلبات فقط + عرض المنتجات والعملاء دون تعديل |
| **مسؤول المخزون** | المنتجات والمخزون + عرض الطلبات دون تغييرها |

إضافية لمستخدم بعينه دون إنشاء دور جديد، استخدم حقل `permissionsOverride`.

## التقييمات

التقييم متاح **لمن اشترى المنتج فقط**: يتحقق الخادم برقم الهاتف من وجود
طلب غير ملغي يحوي هذا المنتج. بدون هذا القيد يمتلئ المتجر بتقييمات وهمية
وتفقد قيمتها.

- تقييم واحد لكل عميل لكل منتج
- المراجعة قبل النشر افتراضيًا (يتحكم بها المدير من الإعدادات)
- المدير ينشر أو يخفي أو يحذف — **ولا يعدّل نص التقييم أو نجومه**
- رقم هاتف المقيّم لا يُرسل للمتصفح أبدًا

## التحليلات

داخلية بالكامل — **لا Google Analytics ولا أي خدمة خارجية**، فبيانات
عملائك لا تغادر خادمك.

- لا نخزّن عنوان IP ولا معرّفًا دائمًا للزائر
- `sessionId` في `sessionStorage` وينتهي بإغلاق التبويب
- نقيس: مشاهدات الصفحات والمنتجات، الإضافة للسلة، بدء الدفع، معدّل التحويل

## الإطلاق

**[`DEPLOYMENT.md`](DEPLOYMENT.md) هو الدليل الكامل** — الانتقال إلى
PostgreSQL، متغيّرات البيئة، الاستضافة، Nginx، النسخ الاحتياطي، واستكشاف
الأعطال.

الخلاصة: المخطّط مكتوب بأنواع متوافقة مع PostgreSQL عمدًا (بلا `enum` وبلا
حقول `Json` أصلية)، فالانتقال ثلاث خطوات: تغيير `provider`، واستبدال المحوّل
في `src/lib/db.ts` بـ `PrismaPg`، ثم `npx prisma migrate deploy`.

⚠️ قبل أول طلب حقيقي: حساب مدير، رسوم توصيل حقيقية، بيانات التواصل، نصوص
السياسات، حذف المنتجات التجريبية، ونسخ احتياطي دوري. القائمة كاملة في أول
`DEPLOYMENT.md`.

- **`ordersEnabled`** مفتاح إيقاف فوري بيد المدير. عند إطفائه ترفض الواجهة
  والخادم إنشاء أي طلب.
- **`'unsafe-eval'` في CSP للتطوير فقط** — يحتاجه React Refresh. حزمة
  الإنتاج لا تحتاجه فيُسقَط، ويُتحقق من ذلك بترويسة الاستجابة بعد البناء.
- **أوزان الخطوط مكلفة**: كل وزن من IBM Plex Sans Arabic ملفّان (عربي
  ولاتيني) ≈ 48 ك.ب يُحمَّلان مسبقًا على كل صفحة. أربعة أوزان الآن (192 ك.ب).
  لخفض إضافي بـ 56 ك.ب يمكن إسقاط المجموعة اللاتينية — لكن أسماء العطور
  المستوحاة ستُرسم بخط مختلف، وهو قرار تصميمي لا تقني.
- **حدود المعدّل** في الإنتاج: 5 طلبات / 5 دقائق، 10 محاولات تتبّع / 5 دقائق
  لكل عنوان IP. يرفعها `RATE_LIMIT_MULTIPLIER` عند الحاجة — لا تستخدمه في
  الإنتاج.
- **رسوم التوصيل الحالية تجريبية** (طرابلس 10، بنغازي 15، سبها 20 د.ل، ومنطقة
  تاجوراء 13) وُضعت لاختبار الحساب فقط. باقي المدن بصفر. حدّدها من لوحة
  التحكم قبل الإطلاق.
